⬡Search & filter

The toolbar search box narrows the commit log five different ways, and the all-branches toggle controls how much history is in scope. Message, author and code searches run server-side so the lane graph is re-laid-out over just the matches.

Search modes

A mode switch sits to the left of the search input; each mode tints the box and has its own placeholder.

Entry point

  • ToolbarClick a mode icon (Message Hash File Author Code), then type.

Message filter log --grep

  1. Typing debounces, then Go re-runs log with grep.
  2. The graph is re-laid-out over the matching commits — connectors reflect just the filtered set.

Hash prefix jump

  1. Entered as a hash prefix (e.g. a0c103).
  2. Resolved client-side against the loaded history to jump to the matching commit.

File search log.file

  1. Enter a file name or path.
  2. Go returns the commits touching that path (backs the same query as file history).

Author filter log --author

  1. Enter an author name or email.
  2. Go re-runs log with author server-side; the graph re-lays out over the matches.

Code search — pickaxe log -S

"When did this string appear or vanish?" Searches content changes, not messages — only commits where the number of occurrences of the string changed (introduced or removed) match. Unrelated commits that merely shipped alongside the string don't.

Entry point

  • ToolbarPick the Code mode (</> icon), type a string — e.g. a function name.
  1. Typing debounces, then Go re-runs log with pickaxe (git log -S<string>) server-side.
  2. The graph re-lays out over the matches — typically just the commit that introduced the string and the one that removed it.

Branch scope

Entry points

  • Toolbar pillAll branches / This branch toggle.
  • Branch comboboxPicking a branch restricts the log to that branch.

"All branches" passes --all; otherwise the log is scoped to the selected branch only.
